# Tier 3 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make LocalAI survive GPUs that cannot hold the chosen model, accept more than PDFs, measure the cross-encoder on WebGPU, drop dead assets, and refresh the measured README.

**Architecture:** Each part is a thin, tested addition to the existing split: pure logic in `src/lib/*` with Vitest, the worker behind the typed protocol in `src/lib/types.ts`, React wiring in `src/App.tsx`, and local-only Playwright specs for anything that needs a GPU. No new network hosts: the CSP in `src/lib/csp.ts` stays exactly as it is, so every parser and runtime file is bundled or served first-party.

**Tech Stack:** Vite 8, React 19, TypeScript 6, Vitest 5, Playwright 1.64, `@mlc-ai/web-llm`, `@huggingface/transformers`, `pdfjs-dist`, `mammoth` (new, lazy-loaded), `docx` (new, dev-only fixture generator).

**Spec:** Inline, next section. The user asked for Tier 3 of the CV-positioning assessment (GPU-OOM auto-fallback, cross-encoder on WebGPU measured against WASM, more input types, asset cleanup, bench refresh and docs), executed with subagent-driven development, a review per part and a commit per part.

## Spec

1. **Model fallback.** When loading a model fails for a reason that looks like GPU memory (out of memory, device lost, buffer/storage limits, insufficient memory), the app loads the next smaller model from the catalog instead of showing a dead error screen, tells the user which model it fell back to and why, and never saves the failed model as the user's preference. The chain is bounded: Qwen 3B / Phi-4 mini / Llama 3B → Qwen 1.5B → Qwen 0.5B → error. A URL parameter `?simulateOom=<modelOptionId>` makes that model's load fail with a synthetic memory error so the path can be tested on any machine.
2. **Input types.** `.txt`, `.md` and `.docx` files are accepted next to PDFs, by picker and by drag-and-drop, with the same chunk → embed → IndexedDB path. Text and Markdown become one unpaged document (no page labels); DOCX text is extracted on-device with mammoth, loaded only when a DOCX is dropped. Unsupported files produce the existing inline message. OCR for image-only PDFs is deferred: tesseract.js would need its runtime and language data served first-party and is out of scope for this plan.
3. **Cross-encoder on WebGPU.** Measure the reranker (and the sentence-focus pass) with Transformers.js `device: 'webgpu'` against today's WASM path in the browser bench. Ship WebGPU only if it loads reliably alongside WebLLM and is faster at p50; otherwise keep WASM, keep the code path behind a constant set to off, and record the numbers in NOTES. Either way WASM remains the fallback.
4. **Cleanup.** Remove `src/assets/{hero.png,react.svg,vite.svg}` and `public/sample-medical-summary.pdf`; nothing references them.
5. **Measure and document.** Re-run the browser bench on this machine with the sentence-focus pass included, update the README bench row (which now has a Focus p50 column), the narrative, NOTES, the project memory, and deploy.

## Global Constraints

- CSP in `src/lib/csp.ts` is unchanged; `npx vitest run src/lib/csp.test.ts` must stay green. Any new runtime file is served from this origin.
- No new dependency in the main bundle's critical path: `mammoth` is `await import()`ed inside the DOCX branch only.
- TypeScript strict; `npm run typecheck`, `npm run lint`, `npx vitest run` green before every commit; `npm run build` green before any deploy.
- Tests that need WebGPU live in `e2e/` and start with `test.skip(!!process.env.CI, 'needs a real GPU (WebGPU)')`; they use the installed Chrome and the persistent profile `e2e/.chrome-profile` (already cached: Qwen 2.5 0.5B, MiniLM, the cross-encoder, on origin http://localhost:4173).
- Commit messages follow the repo's style: an imperative sentence, no prefix, body explains why.
- Bench runs happen on `vite preview --port 5174` (the origin whose Cache API holds the 1.5B weights), never on the dev server.

## Review Focus

1. A memory failure on the smallest model (Qwen 0.5B): the app must show the error, not loop. Pinned by `nextSmallerModel('qwen-fast')` returning `null` (Task 1) and the loop in Task 3 stopping on `null`.
2. A failed model must not become the saved preference, or the next visit fails again before the fallback: Task 3 persists the tier only after `initLLM` resolves; the e2e in Task 3 reloads the page and asserts the small model boots directly.
3. A `.txt` saved by Windows with a UTF-8 BOM and CRLF line endings: the BOM must not reach the first chunk and lines must still split. Pinned by `readTextFile` tests in Task 4.
4. A `.docx` with no text (images only) must fail the way an image-only PDF does, with the existing "No extractable text" message. Pinned by the `extractDocx` test in Task 5.
5. Dropping a `.png`: message, no ingest, no crash. Pinned by `isSupportedFile` in Task 4 and the drop handler using it.
